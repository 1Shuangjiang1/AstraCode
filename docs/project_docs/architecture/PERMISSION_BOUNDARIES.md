# 权限模式与真实安全边界

> 更新时间：2026-08-08。本文描述的是当前代码实际行为，不是理想设计。

## 一句话理解

- **安全模式**：只自动允许系统判定为低风险的操作；写文件、删文件、安装依赖等会直接拒绝，不弹审批框。
- **审批模式**：低风险和中风险自动执行，只有高风险操作弹框；关键危险操作仍直接拒绝。
- **完全访问**：低、中、高风险都自动执行；关键危险操作仍默认拒绝。

所以，“审批模式”目前更准确的名字其实是“高风险时审批”，并不是“每次修改都审批”。

## 风险分级

| 风险 | 当前典型操作 | 备注 |
| --- | --- | --- |
| 低风险 | 项目内读取文件、查看目录、检查路径；普通未命中风险规则的命令 | 普通命令不代表绝对安全，详见已知边界 |
| 中风险 | 项目内 `write_file`、`edit_file`、`delete_file`；安装/卸载依赖；联网下载；git commit/push；停止进程；串联多个命令 | 审批模式会自动执行这些操作 |
| 高风险 | 文件工具访问工作区外；shell 删除命令；`git reset --hard`、`git clean`、强推；提权；写系统目录；宽泛权限修改 | 审批模式弹框，完全访问自动执行 |
| 关键风险 | 格式化磁盘、关机/重启、原始磁盘写入、针对根目录的宽泛递归删除 | 三种模式默认都拒绝，除非显式设置 `S_FULL_ALLOW_CRITICAL=1` |

## 三种模式逐项说明

### 安全模式 `safe`

自动允许：

- 项目范围内的 `read_file`；
- 项目范围内的 `list_directory`；
- 项目范围内的 `path_exists`；
- 其他被规则识别为低风险的工具。

直接拒绝：

- `write_file`、`edit_file`、`delete_file`；
- 被识别为安装依赖、联网、提交代码、停止进程等中风险命令；
- 高风险和关键风险操作。

安全模式不会弹框让用户临时批准，中风险及以上直接失败。

### 审批模式 `approval`

自动执行：

- 所有低风险操作；
- 项目内写文件、改文件、删除单个文件；
- 安装依赖、访问网络、git commit/push、停止进程等中风险命令。

需要用户审批：

- 切换到当前边界之外的工作目录；
- 文件工具访问工作区外；
- shell 删除命令；
- destructive git、提权、系统目录写入等高风险操作。

审批框提供：

- 拒绝；
- 仅本次允许；
- 本会话同类允许。

“本会话同类允许”按工具名、风险级别、判定原因和参数字段名缓存，不按参数的具体值缓存。例如，永久允许一次“切换到外部目录”后，同一会话中另一个具有相同参数结构的外部目录切换也可能复用批准。

### 完全访问 `full_access`

自动执行低、中、高风险操作，不弹普通审批框。关键风险仍默认拒绝。

完全访问不等于突破所有项目边界：项目模式的专用文件工具仍受 `WorkspaceTools.safe_path()` 限制，不能直接读写项目外路径。但 shell 是更宽的能力，详见下文。

## 项目模式和聊天模式的边界

### 项目模式

- 专用文件工具被硬限制在所选项目根目录中。
- 即使选择完全访问，`read_file D:\other\a.txt` 也会被工作区路径检查拒绝。
- 工作目录只能切换到项目根目录或其子目录。

### 纯聊天模式

- 一开始没有活动文件目录，文件或命令工作前必须先调用 `set_working_directory`。
- 审批模式下，第一次选择外部目录属于高风险，需要用户批准。
- 批准并切换后，该目录成为新的活动边界，后续专用文件操作以此为范围。

## Plan 模式的额外边界

Plan 阶段只向模型暴露只读调查工具。无论选择哪种权限模式，计划生成阶段都不能写文件或执行实施操作。只有用户批准计划后，才进入正常 Agent 执行阶段，并重新使用所选权限模式。

## 子 Agent 与 Teammate

- 主 Agent、子 Agent、Teammate 共用同一个 `PermissionEngine` 和工作区协调器。
- 子角色不能通过换一个执行者绕过权限。
- 同一时间只有一个角色进入工作区读写临界区。
- 审批请求串行显示，避免多个 Agent 同时争抢审批窗口。

## 当前并非沙箱的部分

这是最重要的限制：当前权限系统是**应用层风险分类器**，不是 Windows 沙箱。

1. shell 风险依靠正则规则识别。没有命中规则的新写法可能被低估。例如某些 PowerShell 写文件方式未必会被识别成中风险。
2. 项目模式的专用文件工具有路径硬边界，但 shell 命令可以自行使用绝对路径；规则不能证明它永远不会越界。
3. 完全访问模式允许高风险操作，只保留少量关键危险硬拦截。
4. 审批缓存按“同类操作”而不是具体目标缓存，范围偏宽。
5. 当前没有 Windows Job/AppContainer、容器、虚拟机或文件系统快照隔离。

因此，目前适合个人开发和受信任工作区，不应把它描述为可安全运行任意不可信 Prompt 的生产沙箱。

## 建议的下一版权限设计

1. 把审批模式改成可配置策略：`每次修改审批 / 仅高风险审批`。
2. shell 执行前生成影响摘要，明确目录、网络、进程和 Git 影响。
3. 对 shell 增加允许目录、命令白名单和 Windows Job 隔离。
4. “本会话允许”按规范化目标路径和命令模板缓存，而不是只看参数字段。
5. 增加修改 Diff、执行前预览和一键回滚。
6. 日志自动遮蔽 Key、Token、密码和常见凭据格式。

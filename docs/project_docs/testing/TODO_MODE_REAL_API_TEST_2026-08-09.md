# Todo 强制模式修复与真实 API 测试报告

> 日期：2026-08-09  
> 范围：用户日志复盘、任务合同、Todo 状态机、桌面参数链路、真实 DeepSeek CRUD  
> 结论：通过

## 1. 故障现象与根因

故障日志中 TodoWrite 正常创建了 4 步清单，但系统把“在文档里面写一个算法教程”判成只读咨询，连续拦截 `write_file` 和带写入意图的命令，最终达到模型轮次上限。

直接原因是 UI 的内部执行说明包含“TodoWrite 不能代替 write_file、edit_file、bash”。旧完成门没有区分“宿主指令”和“用户任务”，将这里的“不能”误认为用户禁止修改文件。旧 Todo 按钮也只注入提示词，没有向执行器传递可验证的模式状态。

## 2. 修复后的规则

1. 任务合同只分析控制块之外的用户任务。
2. UI 显式传递 `todo_mode=true`，sidecar 持久化并转交主 Agent。
3. 第一个有效任务工具必须是 TodoWrite；清单必须为 3–7 项。
4. 工作尚未全部完成时必须恰好有一个 `in_progress`。
5. 清单未建立或有开放项时，模型返回纯文本也不能结束任务。
6. Todo 模式至少允许 16 个模型轮次，容纳工作和进度更新的交替调用。
7. 成功的 PowerShell 文件写入也可计入修改证据。

## 6. 当前边界

- Todo 模式用于单次任务，发送后 UI 自动关闭；下一轮需要用户再次开启。
- 宿主保证流程约束与状态收尾，不保证模型对每个 Todo 的文字描述一定是最佳拆分。
- 当前不支持用户在运行中手动增删 Todo；这属于后续交互增强，不影响本轮执行可靠性。
